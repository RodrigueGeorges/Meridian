Une API REST, un SDK JavaScript et trois passerelles pour les caisses existantes. Le même code fonctionne avec chaque PSP du catalogue.

Démarrer

  1. Demandez un accès sandbox : vous recevez une clé de test mk_test_… et des points de vente de démonstration.
  2. Installez le SDK, ou appelez l’API REST avec l’en-tête Authorization: Bearer <clé>.
  3. Lancez un paiement, puis provoquez une panne dans le simulateur pour voir la reprise.
import { Meridian } from '@meridian/sdk';

const meridian = new Meridian({ apiKey: process.env.MERIDIAN_KEY });

const p = await meridian.pay({
  posId: 'pos_paris_02',
  reference: 'CMD-0412',      // votre référence : rejouable sans double débit
  amount: 2450,               // en centimes
  currency: 'EUR',
});
const final = await meridian.waitForFinal(p.posId, p.reference);
// final.state : authorized | declined | cancelled | failed

Les cinq appels

pay, status, cancel, refund, receipt. Le SDK gère les rejeux, les délais et les réponses perdues ; waitForFinal attend l’issue réelle du paiement.

États d’un paiement : created, pending, authorized, declined, cancelled, failed. Une erreur réseau ne donne jamais failed tant que l’issue chez le PSP n’est pas connue.

Les erreurs ont toujours la forme {"error": {"code": "…", "message": "…"}} avec un code HTTP explicite.

Webhooks

Meridian envoie l’issue de chaque paiement à votre URL. Chaque envoi est signé dans l’en-tête meridian-signature et rejoué jusqu’à 12 fois avec un délai croissant si votre serveur ne répond pas.

// meridian-signature: t=1763812345,v1=<hex>
const [t, v1] = header.split(',').map((x) => x.split('=')[1]);
const expected = createHmac('sha256', WEBHOOK_SECRET)
  .update(`${t}.${rawBody}`).digest('hex');
const ok = timingSafeEqual(Buffer.from(v1, 'hex'), Buffer.from(expected, 'hex'));

Caisses existantes

Une caisse déjà intégrée en Concert, ZVT ou nexo passe par Meridian sans réécriture : voir Concert, ZVT et nexo Retailer.

Pour les PSP

Un PSP entre dans le catalogue en décrivant son API dans un module déclaratif (JSON), sans code dans le moteur. Le module doit déclarer l’idempotence et la consultation d’état ; il est publié après avoir passé les 8 scénarios de panne contre la sandbox du PSP. Recevoir le format des modules.
