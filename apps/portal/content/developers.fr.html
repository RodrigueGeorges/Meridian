Une API REST, un SDK JavaScript et trois passerelles pour les caisses existantes. Le même code fonctionne avec chaque PSP du catalogue.

Démarrer

  1. Demandez un accès sandbox : vous recevez une clé de test mk_test_… et des points de vente de démonstration.
  2. Installez le SDK, ou appelez l’API REST avec l’en-tête Authorization: Bearer <clé>.
  3. Lancez un paiement, puis provoquez une panne dans le simulateur pour voir la reprise.
import { Meridian } from '@meridian/sdk';

const meridian = new Meridian({ apiKey: process.env.MERIDIAN_KEY });

const p = await meridian.pay({
  posId: 'pos_paris_02',
  reference: 'CMD-0412',      // votre référence : rejouable sans double débit
  amount: 2450,               // en centimes
  currency: 'EUR',
});
const final = await meridian.waitForFinal(p.posId, p.reference);
// final.state : authorized | declined | cancelled | failed

Les cinq appels

pay, status, cancel, refund, receipt. Le SDK gère les rejeux, les délais et les réponses perdues ; waitForFinal attend l’issue réelle du paiement.

États d’un paiement : created, pending, authorized, declined, cancelled, failed. Une erreur réseau ne donne jamais failed tant que l’issue chez le PSP n’est pas connue.

Les erreurs ont toujours la forme {"error": {"code": "…", "message": "…"}} avec un code HTTP explicite.

Webhooks

Meridian envoie l’issue de chaque paiement à votre URL. Chaque envoi est signé dans l’en-tête meridian-signature et rejoué jusqu’à 12 fois avec un délai croissant si votre serveur ne répond pas.

// meridian-signature: t=1763812345,v1=<hex>
const [t, v1] = header.split(',').map((x) => x.split('=')[1]);
const expected = createHmac('sha256', WEBHOOK_SECRET)
  .update(`${t}.${rawBody}`).digest('hex');
const ok = timingSafeEqual(Buffer.from(v1, 'hex'), Buffer.from(expected, 'hex'));

Caisses existantes

Une caisse déjà intégrée en Concert, ZVT ou nexo passe par Meridian sans réécriture : voir Concert, ZVT et nexo Retailer.

Terminal du magasin : API locale et API cloud

L’agent Meridian s’installe sur un poste du magasin et pilote le TPE du réseau local en Caisse-AP sur IP, ZVT ou nexo. Il expose les mêmes cinq appels de deux façons :

  • API locale (caisse installée) : http://127.0.0.1:8787/v1/payments…, avec le même SDK. Fonctionne sans Internet, journal signé sur le poste.
  • API cloud (caisse en ligne) : la caisse appelle l’API Meridian ; l’agent reçoit la demande par une connexion sortante, sans port à ouvrir. Brancher le point de vente avec PUT /v1/pos/{id}/psp et le module edge-terminal ({"agentId": "magasin-paris-1"}). GET /v1/edge/agents liste les agents connectés.
TERMINAL=caisse-ap TERMINAL_HOST=192.168.1.50 TERMINAL_PORT=8888 \
MERIDIAN_URL=https://… MERIDIAN_API_KEY=mk_… MERIDIAN_AGENT_ID=magasin-paris-1 \
npx tsx apps/edge/src/main.ts

En nexo, l’agent gère aussi la session (TERMINAL_SESSION=1 si le terminal exige un Login), vérifie l’identifiant du terminal, signale un terminal occupé (refus terminal_busy, sans débit) et, après une réponse perdue, redemande l’état au terminal jusqu’à l’issue réelle. Agent hors ligne : rien n’est envoyé, le PSP de secours choisi par le marchand prend le relais. Réponse perdue : la demande est rejouée avec la même clé et l’agent ne relance jamais le terminal. Encaisser sur l’appareil (Tap to Pay)

Avec un module d’encaissement sur l’appareil, pay renvoie un champ device (secret client du paiement) tant que le paiement est en cours. L’application le passe au SDK du PSP sur le téléphone, qui lit la carte. Meridian suit l’issue côté serveur comme pour un terminal. POST /v1/pos/{id}/device-token fournit le jeton de connexion du SDK ; la clé secrète du PSP ne quitte jamais Meridian. Statut, assistants de code

  • GET /v1/status : taux de réponse et délai moyen de chaque PSP, publics, sans volumes. Voir la page de statut.
  • /llms.txt : résumé de Meridian et de l’API pour les assistants de code.
  • Serveur MCP (packages/mcp) : un assistant de code consulte le catalogue, les points de vente et leur PSP, l’état et le journal d’un paiement, et lance des paiements de test. Paiement uniquement avec une clé de test ; aucun outil d’annulation ni de remboursement.
MERIDIAN_API_KEY=mk_test_… MERIDIAN_URL=https://… npx tsx packages/mcp/src/main.ts

Pour les PSP

Un PSP entre dans le catalogue en décrivant son API dans un module déclaratif (JSON), sans code dans le moteur. Le module doit déclarer l’idempotence et la consultation d’état ; il est publié après avoir passé les 8 scénarios de panne contre la sandbox du PSP. Recevoir le format des modules.
