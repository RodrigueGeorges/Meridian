Comment ça marche

Une règle simple : écrire avant d'agir.

  1. 01

    La caisse appelle Meridian

    Un seul appel « payer », quel que soit le PSP derrière. Même référence, même résultat, même en cas de double envoi.

  2. 02

    Meridian écrit, puis envoie

    Chaque étape est inscrite dans un journal chaîné et signé avant d'être envoyée au PSP, avec une clé d'idempotence par étape.

  3. 03

    L'issue est garantie et prouvable

    En cas de coupure, Meridian reprend depuis le journal et retrouve l'issue réelle. Chaque paiement se termine par une preuve vérifiable.

Pour les éditeurs de caisses et de bornes

Ne perdez plus une vente à cause du PSP du marchand.

Chaque marchand arrive avec son PSP. Chaque PSP coûte une intégration, une certification et de la maintenance. Avec Meridian, vous intégrez une fois et proposez tout le catalogue.

Cinq appels. Pas un de plus.

payer, état, annuler, rembourser, reçu. Le SDK gère les rejeux, les délais et les réponses perdues. Votre code ne connaît pas le PSP.

// npm i @meridian/sdk
const m = new Meridian({ apiKey, posId });

await m.pay({ reference: 'T-1042', amount: 2450, currency: 'EUR' });
const p = await m.waitForFinal('T-1042');
// p.state → 'authorized' | 'declined' | 'cancelled'
const r = await m.receipt('T-1042');   // ticket + preuve

Un module déclaratif, pas un projet.

Vous décrivez votre API dans un fichier : étapes, clés d'idempotence, lecture d'état, codes de refus. Aucun code dans le moteur. Le module est refusé s'il ne garantit pas l'idempotence.

{
  "id": "votre-psp",
  "countries": ["FR", "BE", "DE"],
  "pay": [
    { "id": "create", "method": "POST", "path": "/payments",
      "idempotency": "{reference}:create" }
  ],
  "lookup": { "path": "/payments/{vars.id}" },
  "declineCodes": ["card_declined"]
}

La conformité se prouve, elle ne se déclare pas.
